Interpretation: separate components have isolated linear memories; core modules within one component can share memory/calls using a compatible ABI. Small fixed records/scalars flatten into core Wasm values, so no mandatory Candid serialization. Lists generally allocate/copy into destination memory; adapter fusion avoids intermediate representations, not automatically cross-memory copies. WIT handles borrow resources, not arbitrary Motoko heap pointers. Prototype currently copies Blob -> Motoko Nat8 array -> CABI buffer before the boundary; returns are copied from CABI storage into a new Blob. These are implementation TODOs, not unavoidable Component Model rules.

Recommendation: keep trusted direct-heap typed plugins for these pure kernels, especially generic CandidX where compile-time specialization is the distinctive feature. Future component packaging can coexist with this core-module fast path. SHA is a good future component candidate if Blob lowering/return allocation become efficient; benchmark identical kernels before choosing. Pure calls do not imply per-call instance creation. GC safety still requires explicit lifetime/ownership rules if bytes are borrowed rather than copied.

Cost model for identical kernels: component = kernel + fixed adapter cost + input/output materialization + allocation/cleanup. Plugin = kernel + compiler adapter/result allocation. Small inputs depend heavily on fixed cost; large SHA amortizes fixed call overhead; per-byte transfer cost remains; fast encoding can be sensitive to another traversal/copy. No measured component slowdown percentage or derived native-library/component speedup.
